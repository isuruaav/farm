# FOREST LANKA — PHP website

The original 22 HTML pages now use PHP with shared navigation, footer and product data. The complete website, staff portal and form result page use **Tailwind CSS 4.3.5**, verified against the official release and npm registry on November 19, 2026. Includes a 20-product catalog, combined category/search filters, sorting, a persistent quotation cart, English-only content, working inquiry forms, a staff dashboard and scroll reveal animations.

## Open on WAMP

Start Apache and open **http://localhost/farm/**. `index.php` is the default page. Old `.html` addresses redirect to the corresponding PHP pages and retain query strings.

Requirements: PHP **8.1+** with `pdo_sqlite`, `mbstring` and sessions; Apache 2.4 with `mod_rewrite` and `.htaccess` overrides enabled. No MySQL database, Composer packages or Node runtime is required to use the website. PHP automatically creates the SQLite database and session directory inside `storage/`. PHP must be able to write there.

For another local environment:

```powershell
php -S 127.0.0.1:8080 router.php
```

Open http://127.0.0.1:8080/. Use the supplied router: it blocks private application files as well as handling old addresses. Configure equivalent restrictions if deploying with Nginx or another server. For production, serve HTTPS, disable PHP `display_errors`, and set `FOREST_STORAGE_DIR` to a writable directory **outside the public document root**. Preserve the `.htaccess` restrictions when using the default WAMP storage location.

## Create the staff account

From this project folder:

```powershell
php tools/create-admin.php admin
```

Enter and confirm a password of at least 12 characters (maximum 72 bytes). The command stores only a password hash and does not overwrite an existing account. There are no default credentials or public signup routes. Then open **http://localhost/farm/admin/**.

Staff can search/filter all request types, review contact details and product quantities, add internal notes, change status, and export the filtered records as CSV (up to 10,000 rows per export). Sign-in is rate limited; inactive staff sessions expire after 30 minutes. For larger exports, narrow the filters. CSV output protects against spreadsheet formula injection.

The staff tools also include **Product catalog**, **Project stages** and **Website content**. Manage products, price visibility, order minimums, featured placement, publication/availability, project stages, homepage text and shared contact details. Catalog entries can be archived and restored. See `PROJECT_REVIEW.md` for the proposal comparison and remaining scope.

## Forms and quotations

Contact, export, investment, partnership, all eight sector quotation forms and the product cart save to SQLite. Success appears only after saving. Reference numbers are generated by PHP. CSRF checks, strict validation, a spam honeypot, request limits and retry protection are included. Product IDs and quantities are checked against the server catalog; browser-supplied prices are ignored.

The website **does not charge cards or send automatic emails**. Staff read requests in the dashboard and follow up manually. The WhatsApp button opens a draft; the visitor sends it from WhatsApp. Prices, delivery and payment arrangements require confirmation. Project stages initially default to Planned; confirm and update them through the staff portal. Industry/gallery photographs are illustrative.

All website navigation, page content, product descriptions, forms and interface messages are in English. The language switcher is removed. Previously saved language preferences have no effect on the website. Original sources remain unchanged in the protected legacy backup. Customer-submitted text is preserved as entered.

## Files and maintenance

### Contextual section images

The catalog also uses twenty generated product photographs in `assets/images/products/photo-v2/`. Product cards, details, quick views, related products and homepage featured cards share the new local WebP paths. Saved filenames, final prompts and verification details are in `assets/images/products/photo-v2/README.md`. Existing JPEGs are retained; the live catalog and seed image references were updated together.

Seventeen content-specific photographs were generated with the built-in image generation tool and added across all 22 public pages, including the homepage catalog and circular-growth sections, 21 page introductions, industry explorer, gallery, news and investment cards. The images are illustrative concepts. Local WebP files include 1536px and 768px versions; page introductions use responsive sources and below-the-fold images load lazily.

Image assignments and accessible descriptions are in `data/page-visuals.json`. Industry images are selected in `data/industries.json`. Shared introduction markup is in `includes/page-intro-visual.php`, and the responsive layout is in `assets/css/imagery.css`. Final prompts and saved asset paths are listed in `assets/images/sections/README.md`. Source templates were backed up to `storage/backups/pre-contextual-imagery.zip` before this change.

- `includes/`: shared PHP layout, session/security helpers and inquiry validation.
- `views/`: the page content; root PHP files select the matching view.
- `data/products.json`: initial catalog seed data. After the first migration, edit the live catalog in the staff portal; JSON changes do not overwrite database products.
- `data/industries.json`: central industry metadata and proposed focus/process information. Stage and summary overrides are stored in the database.
- `data/forms.json`: server field rules and select options; update these when changing forms.
- `assets/css/tailwind-input.css`: Tailwind v4 CSS theme, explicit PHP/JavaScript source paths, and component imports.
- `assets/css/styles.css`, `admin.css` and `design.css`: shared, staff and portfolio component styles; edit these source files.
- `assets/css/utilities.css`: the compiled production bundle, including Tailwind, shared styles, admin styles and scroll animations. All application pages load this bundle.
- `package.json` and `package-lock.json`: pinned asset development dependencies and reproducible installation.
- `assets/vendor/fontawesome/`: local icons and their original license.
- `storage/forest-lanka.sqlite`: requests, staff password hashes, products, project stages, site content and content activity records.
- `storage/backups/original-static-site.zip`: untouched original HTML, CSS, JavaScript and generator scripts.

Back up `storage/` securely. Do not expose it or commit customer records to a repository. The old Python generators are retained under `tools/legacy-generators/` and in the original backup; they are not part of the PHP or Tailwind build. Google Fonts and illustrative Unsplash images still require an internet connection; system font fallbacks and local logo image fallbacks are provided.

Only asset development needs Node.js 20+ and npm. Install the locked dependencies, then build the local stylesheet and icons:

```powershell
npm ci
npm run build
```

After changing templates, utility classes or source CSS, run `npm run build` again. For live CSS rebuilding during development, use `npm run watch:css`. The existing `tools/build-assets.ps1` command also runs this same build.

Tailwind and `@tailwindcss/cli` are pinned to **4.3.5**; local icons use Font Awesome Free 6.5.1. Configuration is defined in CSS with `@theme` and `@source`; the v3 JavaScript configuration is removed. Sources include all public PHP views, shared includes, staff templates, frontend scripts and the result page, while excluding backups, dependencies and legacy generators. Shared components use the `components` layer so utilities retain the expected priority. Browser requests never use the Tailwind Play CDN or compile CSS at runtime.

The v4 browser baseline is Safari 16.4+, Chrome 111+ and Firefox 128+. See the [official upgrade guide](https://tailwindcss.com/docs/upgrade-guide) and [v4.3.5 release](https://github.com/tailwindlabs/tailwindcss/releases/tag/v4.3.5).

## Verification

```powershell
python tests/verify.py
node tests/cart.test.cjs
node tests/experience.test.cjs
npm run test:styles
```

The HTTP checks start a short-lived PHP server with disposable isolated storage, test all 22 public pages, local assets and links, forms, server pricing, CSRF, retry protection, private paths, staff authentication/status changes, CSV export and request limits. They do not send emails or WhatsApp messages and do not touch real customer records. JavaScript checks cover cart recovery, canonical prices, legacy product IDs, quantity limits, blocked browser storage and combined filtering. Stylesheet checks parse the generated CSS and verify the version, template class coverage, cascade layers, responsive utilities, staff/result page integration and scroll animation styles.

For production SEO, set `FOREST_SITE_URL` to the full site base URL. `sitemap.xml` and `robots.txt` are served dynamically; the sitemap lists public pages and published product details. The local PHP router and Apache rules both support these routes.

Browser visual testing was unavailable in the editing session. Responsive CSS, keyboard navigation, modal focus handling and reduced-motion support are implemented; perform a desktop/mobile browser review before public launch. The latest review is documented in `PROJECT_REVIEW.md`.
